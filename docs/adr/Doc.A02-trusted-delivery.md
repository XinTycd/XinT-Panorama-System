# A02：项目诊断与发布快照

## 状态

Accepted；实现状态见当前代码与 `npm test`。

## 背景

项目发布前需要发现无场景、断裂引用、缺失本地资源和外部依赖；发布后需要检测快照或本地文件是否变化。检查远程资源时不得在诊断或发布中隐式下载。

## 决策

- `backend/project-delivery.js` 负责只读诊断、资源清单与 SHA-256 快照验证。
- `backend/project-store.js` 负责事务内写入发布记录，并在分配版本号时序列化并发创建。
- `backend/routes/projects.js` 负责 HTTP 状态码和请求/响应契约。
- 诊断错误项阻止发布并返回 422 与报告；warning 可发布。默认首场景为导航起点，所有其他场景分别检查可达性。
- 本地路径解析复用 `backend/media.js` 的安全路径函数，只核验存储目录 `uploads/` 下的本地文件。
- 远程资源只标记为未核验。发布快照保留资源状态和计数，验证响应同时提供兼容的 `verified`/`assetsVerified` 字段和完整核验字段。

## 指纹范围与限制

指纹覆盖项目快照内容和资源清单；每个可读本地文件另有 SHA-256。指纹不包含其自身的 `integrity` 字段。键顺序规范化后再哈希。

哈希不是数字签名、身份背书或不可抵赖证明。发布快照不包含图片文件，也不是自包含离线包。
