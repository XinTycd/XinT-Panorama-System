# XinT Panorama System v0.2.5

**Release date:** 2026-11-11

## Highlights

- **Protect stored panorama sources.** Public API responses no longer return a stored media path or source URL. The viewer and API use metadata-free lossless previews and generated WebP thumbnails. Preview images retain decoded pixels and source dimensions; thumbnails are separate derivatives. If a source cannot be safely decoded or a derivative is unavailable, the request fails instead of returning the stored source. Remote imports require HTTPS, validate DNS destinations, and recheck redirects; the raw-image proxy is retired and returns `410 Gone`.
- **Persist console preferences on the server.** The API address, built-in project workspace plugin state, embed-control preset, and toolbar visibility are stored in `console-settings.json` under `PANORAMA_STORAGE_DIR`. The language choice remains local to the browser. Existing browser-stored preferences are not migrated; a server with no settings file uses the documented defaults.
- **Add a localized console.** The console now provides Simplified Chinese, Traditional Chinese, and English interfaces, with language selection in Settings. Copy buttons expose success feedback, hidden-control wording is clearer, and console scrollbars follow the themed UI.

## Upgrade notes

- Use Node.js 24 or later and install dependencies with `npm ci`.
- Direct image URL loading through `widget?imageUrl=...` is no longer supported. Import or register an image in the gallery, then embed it by its panorama number. The `/api/panoramas/proxy` endpoint is retired.
- Console preferences that were previously kept in browser storage are not copied into the server settings file. Review the API address, plugin state, embed preset, and toolbar visibility after upgrading. Language remains per browser.
- The console settings endpoint is limited to same-origin requests from loopback clients and does not enable CORS. The application has no account or role system; protect the management console and management APIs from public access.
- Existing stored media remains in its selected storage backend. Protected preview derivatives are generated and cached by the server and can be rebuilt when needed.
